## 一、游戏概述

### 1.1 一句话定义

> 以中华武术为题材的**卡牌对战 + AI 辅助招式训练**游戏，玩家拜师学艺、自创卡组、擂台对决。

### 1.2 核心体验

- **拜师学艺**：选择门派，在 AI 掌门大师指导下打磨招式
- **自成一派**：从门派武学体系中自选招式，构筑独特卡组
- **比武对决**：用自创卡组与 AI 或真人玩家实时对战
- **开宗立派**：不断精进，成为一代宗师

### 1.3 目标用户

- 对中华武术文化感兴趣的玩家
- 策略卡牌游戏爱好者（类似《炉石传说》《杀戮尖塔》）
- 喜欢创意表达和自定义 builds 的玩家

## 三、核心玩法循环

```
拜师 ──→ 习武（AI 多轮训练）──→ 获招式卡牌
   ↑                              │
   │                              ↓
   │                         编卡组（15-30 张）
   │                              │
   │                              ↓
   │                         比武对决
   │                              │
   └── 获得经验 ────←── 胜/负 ──┘
```

### 3.1 用户故事

1. **新玩家**：浏览四大师门 → 选择一个门派 → 习武获取第一张卡牌 → 构筑初始卡组 → 与 AI 对战
2. **成长玩家**：在不同门派习武获取更多卡牌 → 尝试不同卡组搭配 → 挑战更强 AI / 玩家
3. **高手玩家**：自由切换门派 → 掌握多流派 → 自定义招式（世外高人） → 参与排位赛

## 四、门派与武学体系

### 4.1 四大师门

| 门派 | 风格 | 掌门大师 | 起始招式 | 子分支数 | 总卡牌数 |
|:---|:---|:---|:---|:---:|:---:|
| **少林寺** | 全面均衡 | 达摩祖师 | 童子拜佛 | 3 | ~31 |
| **武当派** | 以柔克刚 | 张三丰 | 太极起势 | 3 | ~30 |
| **北拳** | 刚猛爆裂 | 北拳宗师 | 两仪桩 | 6 | ~47 |
| **南拳** | 灵巧短打 | 南拳宗师 | 二字钳羊马 | 3 | ~28 |

### 4.2 子分支体系

每个门派下细分 3-6 个武学分支（子风格），玩家在一个门派内可跨分支学艺：

**示例 - 北拳分支结构：**
```
北拳
├── 八极拳（贴身靠打，刚猛爆裂）
├── 通背拳（放长击远，鞭劲透体）
├── 翻子拳（双拳密如雨，脆快一挂鞭）
├── 戳脚（手是两扇门，全凭腿打人）
├── 螳螂拳（勾搂采挂，快速连击）
└── 迷踪拳（步法多变，飘忽不定）
```

### 4.3 世外高人系统

突破门派限制的开放模式：
- 不绑定任何门派
- 玩家自由描述创意招式
- AI 评估平衡性和可行性后生成自定义卡牌
- 适合高阶玩家进行创意表达

| 属性 | 类型 | 说明 | 示例 |
|:---|:---|:---|:---|

| `gameId` | enum | 归属游戏版本 | `martial-hegemony` |
| `description` | string | 招式详细描述（供 LLM 判定用） | `以肩背撞击对手...` |
| `displacement` | number | 出招后位移值（米） | `0.8` |
| `source` | enum | 预设/自定义 | `preset` |
| `isStarter` | boolean | 是否起手式 | `true` |
| `keywords` | string[] | AI 语义匹配关键词 | `["铁山靠","靠桩","撞击"]` |
| `artAssetId` | string? | 招式小人图文件名（预留） | — |
| `createdAt` | string | 创建时间 | ISO 8601 |
| `updatedAt` | string? | 更新时间 | ISO 8601 |

### 5.2 位移值的战斗意义

位移值是《自成一派》战斗系统的核心机制：

| 位移值 | 含义 | 示例卡牌 |
|:---|:---|:---|
| `> 0` | 向前推进，缩短距离 | 铁山靠 (+0.8m) |
| `= 0` | 原地出招，不移动 | 揽雀尾 (0m) |
| `< 0` | 后退/闪避，拉开距离 | 迷踪步 (-0.6m) |

> 距离太远无法近身攻击，太近则无法施展大开大合的招式。

## 六、战斗系统

### 6.1 核心规则

```
基础生命值：10 ❤️（双方）
基础距离：   2.0 m
手牌数量：   5 张（随机抽取）
卡组规模：   15-30 张
```

### 6.2 回合流程

```
1. 玩家从手牌中选择一张招式卡牌
   ├── 若 distance < card.displacement → 不可出牌（距离不够）
   └── 若 distance ≥ card.displacement → 可出牌

2. AI 同步选牌（或玩家选完后 AI 自动选）

3. 双方同时出牌，计算：
   a. 位移结算：newDistance = distance - cardA.displacement - cardB.displacement
   b. 若 newDistance < 0 → 双方相撞摔倒，下一回合重置为 1.0m
   c. 命中判定：feasibility 评分（AI Agent 判定）→ 命中/格挡
   d. 伤害计算：命中后根据卡牌威力扣减生命值

4. 进入下一回合（出牌后手牌补至 5 张）
```

### 6.3 胜负条件

- 一方生命值归零 → 另一方获胜
- 一方无牌可出 → 判负
- 达到最大回合数（设计待定）→ 生命值高者胜

### 6.4 AI 对决判定（duel-judge）

> **当前状态**：DuelPage 中 AI 是**随机选牌**，尚未对接 duel-judge Agent。

**目标实现方式**（3 Agent 流水线）：

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  招式分析师  │ → │  对决仲裁官  │ → │  战况叙述师  │
│ 分析双方动作 │    │ 判定命中伤害 │    │ 生成武打描写 │
└──────────────┘    └──────────────┘    └──────────────┘
```

三个 Agent 顺序执行，每个 Agent 使用 LLM（DeepSeek/OpenAI）进行语义理解和裁决。

### 6.5 战斗系统已知问题

1. **game-logic 为空**：`packages/core/src/game-logic/index.ts` 是 `export {}`，战斗逻辑全写在前端 DuelPage 里，无法复用
2. **前端 mock 数据不完整**：DuelPage 用了 `allCards` 的随机抽取 + 手动距离计算 + 简单概率判定
3. **位移值多未赋值**：预设卡牌的 `displacement` 字段在部分数据中均为 `0`，未按实际招式设定
4. **对接 AI Agent**：duel-judge 服务已完成，但前端从未调用

## 七、习武场（AI 训练系统）

### 7.1 玩法流程

```
玩家选择门派/大师
      │
      ▼
描述心中构想的招式（自由文本）
      │
      ▼
AI 大师给出反馈：
├── 招式改进建议
├── 从本门卡牌库中匹配最接近的预设卡牌
└── 推荐最适合的子分支
      │
      ▼
┌──────────────────────────────┐
│ 多轮迭代（最多 5 轮）         │
│ 玩家根据反馈修改描述 → 再提交 │
└──────────────────────────────┘
      │
      ▼
最终匹配结果 → 玩家获得卡牌
```

### 7.2 大师 personality 设计

每个大师有独特的性格和教学风格，体现在 AI 反馈的语气和内容：

| 大师 | 性格 | 教学特色 |
|:---|:---|:---|
| 达摩祖师 | 沉稳慈悲 | 循循善诱，注重基本功和武德 |
| 张三丰 | 恬淡自然 | 引导学生从天地自然领悟武道 |
| 北拳宗师 | 豪迈直爽 | "练拳先练胆"，直接有力 |
| 南拳宗师 | 内敛务实 | "实用至上"，注重身体条件匹配 |

### 7.3 世外高人模式

- 无门派限制
- AI 评估创意性、平衡性
- 生成自定义卡牌（需审批通过）
- 适合高阶玩家

> **当前状态**：training-ground Agent（Python FastAPI）已完成，但前端只有门派入口卡片，没有多轮对话界面。

## 八、连招系统

### 8.1 设计目标

连招系统评估**两个招式的衔接可行性**，给玩家反馈：

- 前一个动作结束时的身体姿态/重心位置
- 后一个动作的起手要求
- 两者是否兼容 → 可行性评分

### 8.2 API 输入输出

```
输入：moveA（前动作描述）+ moveB（后动作描述）
输出：feasibility（0-1 评分）+ difficulty（难度等级）+ 
      key_limitation（关键限制）+ improvement_suggestion（改进建议）
```

> **当前状态**：combo-judge Agent（Python）已完成，前端从未接入。

|:---|:---|:---|

## 附录 B：设计原则

1. **文化为先**：所有设计以中华武术文化为基础，尊重传统
2. **策略为王**：战斗胜负取决于卡组构筑和出牌策略，而非数值碾压
3. **创意表达**：习武场让玩家用自然语言表达创意，AI 帮助落地
4. **渐进学习**：从门派习武入手，逐步到跨流派混搭，最终自创招式
5. **两作互补**：兵器版和拳脚版共享世界观和数据，但战斗体验各异
