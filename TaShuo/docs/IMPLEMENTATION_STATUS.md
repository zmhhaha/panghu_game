# 《它说》实现与验收进度

更新日期：2026-10-22。对应 OpenSpec 变更 `enhance-tashuo-public-information-gameplay`。本文记录媒体/互动基础与报告评分阶段；[公共信息调查规格](PUBLIC_INFORMATION_SPEC.md) 仍是完整目标，不应把局部完成等同于整体验收。

## 已实现的范围

- 两套事件当前内容版本均为 `2.1.0`：《失控的演示》15 条内容、8 个媒体写作任务；《河水变蓝以后》17 条内容、7 个媒体写作任务。游戏尚未上线，开发阶段只维护当前内容包，不保留旧测试存档兼容；版本不匹配的测试局需要重新开始。
- 开场提供电视播报任务、平台短片和已有公开讨论。每套事件有稳定目击账号和三轮有前提关系的补充；不评论时补充也按预定游戏时间公开。机器人事件补足控制链路与独立复现实验，河流事件区分观测、采样与多个因果问题。
- 媒体只接收当前授权来源，按发布者立场撰稿，并经独立来源审校；电视正文至少 600 字、报纸至少 800 字且有完整段落。字数是最低门槛，实际报道质量仍需真实模型阅读验收。
- 基础成稿按事件 ID、内容包版本、内容 ID、提示词版本留存。GET、刷新、其他用户读取相同基础稿件不重新生成。内存仓储合并并发生成，PostgreSQL 使用事务锁与唯一键。当前共享稿件全部不包含玩家输入；个人回复与披露进度存于各自事件。
- 主控先从公开语境选择本轮线索，再把该线索的 `responseMaterialIds` 和先前已披露材料交给账号。正文生成和审校均不接收后续轮次的私有材料，规则层校验账号权限、时刻和披露前提。账号可以无新增线索地回答、回避或承认不知道。
- 评论保留父楼层、目标账号、引用内容、群体回应和持续账号历史；个人补充记录关联原评论与回应。公开 API 不输出幕后真假、误导标签、账号知识授权或未审成稿。
- 成稿、评论和报告先持久化暂停任务，再调用模型；保存已完成步骤。失败保留原输入和已成功结果，按同一任务重试；不切换模型、不生成替代稿。同一幂等键不能改正文或重复结算曝光、压力与线索。
- 低置信度的评论理解先确认再公开，确认令牌绑定用户、事件和原输入；玩家可以取消待确认评论并修改。报告同样先确认低置信度解析，确认前不计分、不结束事件；令牌另绑定原请求、解析和快照，递归规范化键序以适应 PostgreSQL JSONB。取消报告校验原任务，避免多页面误取消新报告。
- 两剧本 17 个问题都有证据规则，区分记录、背景、传言、支持方向、事实专属来源和充分证据组合。网络原因必须有机制/记录支撑；河流颜色、鱼异常与排放分开，超量及错接的合取判断允许阶段性部分成立。生成稿审校新增编辑证据大纲完整性与实际引用来源检查，提示词版本为 `public-reporting-2`；失败不发布大纲或替代稿。
- 提交前冻结实际可读取文本、公开回复、成稿版本和 `evidence-bounded-1` 评分规则，未来、未生成及不可读取材料不进入快照。解析器仅见公开文本和问题，不见真假、充分路径或来源答案。解析逐句校验主张/推理/反证/来源/数值置信度出处，非法引用或编造原句直接失败，不静默修补。
- 确定性规则按 35/25/15/10/10/5 评价事实、证据、因果、反证、置信度与来源；仅对适用维度归一。调查覆盖单列，未给数值置信度不补值，全部未知总分为空。公开回复可引用，但不能自动替代其提及的完整原始附件；充分判断仍须引用具体公开补充材料。
- 默认一档每现实秒推进 10 个游戏秒，二/三档分别为 100/1000 秒；切档先结算旧区间。冷却按跨过的累计游戏时间边界计算，不随刷新次数变化。遇到到期但未成稿的报道时先完成该稿，模型等待不消耗游戏窗口。

## 页面交互

公开评论支持回复具体楼层、选择材料引用、保存公开回应到便签，并把已选笔记追加为可编辑报告草稿。补充材料显示与问题的关系。暂停时可编辑草稿；草稿不因恢复自动发布，传统电视和报纸始终没有评论入口。

前端保留待提交正文与原请求键；处理中显示状态，失败后继续原任务，不能把包含 `generationFailure` 的 HTTP 200 当成提交成功。仍沿用可收起的调查板与报告区域，保留媒体阅读面积。

报告确认卡显示模型理解的主张、推理方式、来源关系、反向材料和玩家原句；可确认原稿或取消后修改。报告结果展示六维分数、单列覆盖、逐项规则理由、版本引用以及独立保存的模型点评。无分数显示“暂无法评价”，不会变成零分。引用可定位正文/评论；版本变更或渠道受阻时明确说明不可读取，不能冒充原版。

## 自动验证范围

核心规则、内容校验、仓储、任务编排与 HTTP 测试覆盖：两套事件三轮追问至报告、静默定时路径、引用与披露边界、刷新正文不变、跨用户隔离、重复提交、低置信度确认、失败重试、报告期间互斥，以及不同轮询频率下的冷却一致性。

第一阶段初次验证：core 10 项、content 11 项、server 49 项，共 70 项通过；三个包的 TypeScript 检查和 Web 的 TypeScript / Next.js 生产构建通过。移除旧存档兼容后，重新验证 content 11 项、server 50 项及这两个包的 TypeScript 检查，全部通过；新增回归确认失效测试局不影响当前列表、不执行模型调用、不能继续操作且仍可由所有者删除。

报告评分阶段验证：core 28 项、content 25 项、server 71 项、Web 8 项，共 132 项测试通过；各包 TypeScript 检查与 Web 生产构建通过。新增覆盖未知评价、方向相反的记录、时序不等于因果、同源与单篇多源、合取判断、冻结快照持久留存/公开投影防漏、原文及数值出处、确认令牌 JSONB 键序稳定性、多页取消冲突、失败断点恢复和空分数呈现。完成后的完整评分快照保留在实例私有状态，只向前端提供版本元数据和评分反馈。

这些自动测试使用明确的测试专用模型替身，不是生产 fallback，也不能证明真实 LLM 能理解所有自然语言问题。PostgreSQL 的事务和 SQL 行为当前使用测试替身验证，尚未完成真实数据库并发/重启验收。

页面点击验收未完成：Browser 工具在初始化时返回 `failed to write kernel assets`（系统找不到指定路径）。已停止并移除为此次检查临时启动的测试服务；没有将模拟文字作为可玩内容交付，也没有用构建通过替代浏览器验收。

## 运行与迁移

- 部署 API 前执行 `apps/server/migrations/002_publications.sql`；现有部署脚本会按序执行迁移。该表仅保存不含个人输入的基础稿件。
- 配置真实 `LLM_BASE_URL`、`LLM_SERVICE_TOKEN`、模型别名，以及生产 PostgreSQL 和认证参数；无有效模型服务不提供可玩的替代内容。
- 本次本地环境没有配置模型服务和 `DATABASE_URL`，因此尚未进行真实模型、真实数据库和部署后联调，也没有发布服务器变更。
- 开发内存仓储只在进程存活期间保存稿件和游戏；跨进程、重启持久化依赖 PostgreSQL，不能将内存模式当作生产存档。
- 已移除历史内容包及兼容注册，两个当前事件直接定义自己的事实、来源和群体。过期测试局不进入事件列表，直接读取或继续操作会提示重新开始；可以删除。稿件缓存仍包含内容版本，避免旧稿混入当前事件。本轮没有连接或清理外部数据库。

## 仍待完成
