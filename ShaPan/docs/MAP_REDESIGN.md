# 战场地图优化方案与实现边界

本轮把中央地图作为指挥员根据通信维护的作战图。继续使用 Next.js、SVG 与现有服务端模拟，不依赖 GenUI，不引入新的地图服务。

## 统一地理数据

`shared/battlefield-maps.json` 是台儿庄与阿纳姆的共同数据源，保存画布尺寸、河道、道路、铁路、城镇区域、地名锚点、桥梁连接、路网边、初始位置和默认行动目标。前端地图、侧栏地点名称与服务器路线规划共同读取，不能再分别维护三套桥头坐标。

画布保持 `900 × 720`，业务坐标为左上角起算的 `0–100`。地形、网格、部队、路线与选中提示使用同一 SVG 视图。缩放采用等比变换，鼠标选点反算同一坐标系；面板宽度变化不能拉伸河流、桥面或箭头。

路线以共享路网连接关键地点，过河使用桥梁连接。明确坐标目标仍需经过合法的陆地接入段，不能因为目标为坐标便绕过河流限制。找不到合法路线时应停滞并给出原因，不能用跨河直线补齐。

军令坐标覆盖完整的 `0–100` 边界。撤退命令优先采用明确指定的目的地，未指定时使用该战役默认撤退地域。“前往并固守”在途中仍为行军，抵达后才转入固守标绘。交战和路线受阻会暂停位移；本轮由后续军令重新规划行动，不自动判定脱离交战。

当前底图是参考战区特征的地形示意，不是经过测绘校准的历史地图。台儿庄突出城门、运河与南岸道路，阿纳姆突出下莱茵河、公路桥、奥斯特贝克与着陆地域。没有实际地理范围校准前，界面不使用虚构的公里比例尺。

## 地图交互与标绘

- 支持拖动、缩放、适应全图和定位选中部队；地形与所有动态标绘一起变换。
- 桌面滚轮与触屏双指缩放使用相同视图，避免只支持鼠标操作。
- “地图专注”收起通信、指挥两侧面板，保持顶部时钟与控制按钮，随时恢复。
- 默认保留部队简号和短行动方向，选中后展示完整计划。区分当前行动、未来计划、已走路线、撤退和炮火支援。
- 友军统一蓝色，敌军统一红色，炮火支援使用单独颜色；两战役不交换颜色含义。
- 密集部队的屏幕标注可偏移并连接实际位置，不能改变单位权威坐标或扭曲路线来避让。
- 返回全局与退出聚焦保持可达；选中其它部队时仍可继续操作。
- “全局态势”同时清除聚焦并适应全图。“轨迹”默认关闭，只在主动查看选中部队时展开历史已行部分。
- “推算”默认关闭，仅根据选中己方部队已报告的路线和行军时长估算位置；使用空心菱形与点线标注“推算位置 · 待回报”。推算不挪动已报告军标，也不预测敌军位置或方向。
- 地图选取目标只填入军令草稿，保留原正文。再次选点替换上一次“地图目标”行，避免重复堆积；玩家仍需确认编码发送。

## 通信驱动的玩家视图

服务器内部真实状态继续用于移动、局部交战与 Agent 判断。HTTP 状态接口和 SSE 事件通过 `server/src/player-view.mjs` 投影玩家可知内容，不直接返回内部 `unitStates`、`localBattles` 或 Agent 上下文。

新战报在生成时记录：

```text
reportedPosition   { x, y, atMinute }，该次报告所述位置和观测时刻
reportedUnitState  该报告所述的部队状态与已知行动
availableAtMinute  通信抵达指挥所的时刻
updatesUnitState   false 表示迟到或被新军令替代，仅归档
```

地图上的部队状态由已抵达报告的有效快照聚合。按观测时间选择最新快照，迟到的旧报告不能覆盖新位置。敌方不返回内部 `route`、`from`、`to`，只显示带来源、时间、可信度的情报范围。过期敌情淡出并在到期后退出当前态势，己方仍保留最后报告位置及其年龄。

前端按战局 ID、事件序列与时钟接收快照，旧轮询响应不能覆盖已收到的更新 SSE 状态。每个单位还单独按报告观测时间合并，快照暂时缺失的单位继续保留最后报告；切换战局时清空上述状态与序列，防止跨战局污染。

友方首次完成行军时自动生成一次抵达战报，保存完成时的位置与关联军令。战报先进入快照中的待发队列，再按原军令通信渠道的延迟进入收件台；不会等待下一次部队 Agent 轮换。敌军的实际抵达不会自动向玩家公开。

点击历史战报使用它自己的位置记录，不能拿当前坐标伪装成历史位置。旧报告若没有位置记录，界面说明只能聚焦该部队最后已知位置。没有有效位置快照时，不用前端初始坐标冒充已获报告的位置。

SSE 在未到达的报告前保留事件序列屏障，游标不得越过它而使该报告永久丢失。初始状态附带安全的 `eventCursor`：已经包含在快照中的时钟、状态和军令事件不再重放，仍在途中的报告随后补送。内部事件可以安全消费，但不把其内容发送给玩家。轮询加互斥，避免慢查询交叠导致事件乱序。

## 部署与后续验收

API 和 Web 镜像均需从 ShaPan 目录作为构建上下文复制 `shared/`。Web 在构建时把 JSON 导入打包，不扩大 Next.js standalone 根目录或修改原启动路径。Worker 使用同一 API 镜像，也必须同步更新；只更新前端会造成新底图与旧路线计算混用。

本轮按照用户要求不运行本地测试、不启动本地服务、不部署。代码落地后，由用户更新 `shapan-web`、`shapan-api` 及 workers，再在服务器完成台儿庄、阿纳姆的完整对局验收。重点检查：

1. 跨河增援、撤退与桥头固守经过实际桥梁，底图锚点与路线一致。
2. 缩放和收起侧栏后，选点坐标与地名对应；再次选点不覆盖军令正文。
3. 未收到报告前不出现真实位置；历史战报定位不随当前部队移动。
4. 敌情范围随报告年龄变化，不呈现未侦知的计划路线。
5. 重连、暂停恢复和通信延迟不导致部队回到旧位置，也不丢失晚到战报。
6. 两战役分别完成胜利、失败复盘，核对关键军令、战报和目标变化的因果关系。

后续可继续增加历史地图校准、道路拥堵、桥梁承载和毁伤、地形对视野与情报范围的约束，以及按已抵达报告回放的时间轴；这些不应与本轮已实现能力混淆。
